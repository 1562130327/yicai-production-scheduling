# 数据流转逻辑梳理

## 一、完整业务流程

```
┌─────────────────────────────────────────────────────────────────┐
│                        订单生命周期                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 跟单员创建订单                                               │
│     └─→ orders 表 (status='待排产', completed='')               │
│                                                                 │
│  2. 管理员智能分配                                               │
│     └─→ assignments 表 (保存分配方案)                            │
│     └─→ orders 表 (status='待排产') [不变]                       │
│                                                                 │
│  3. 师傅点击"开始任务"                                          │
│     └─→ assignments 表 (status='进行中')                        │
│     └─→ orders 表 (status='生产中') [需要更新]                   │
│                                                                 │
│  4. 师傅完成工序                                                │
│     └─→ assignments 表 (status='已完成')                        │
│     └─→ 检查是否所有工序完成                                     │
│     └─→ 如果是: orders 表 (status='已完成', completed='完单')    │
│                                                                 │
│  5. 主页显示                                                    │
│     └─→ 读取 orders 表                                          │
│     └─→ 根据 status 字段显示: 生产中/待排产/已完成               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 三、需要修复的逻辑

### 3.1 师傅工作台 - 开始任务

```javascript
// 当前：只是显示alert，没有真正更新状态
async function startTask(id) {
  alert('任务已开始！');
  loadTasks();
}

// 应该：调用API更新assignment状态和order状态
async function startTask(id) {
  // 1. 更新assignment状态为"进行中"
  await fetch(`/api/agent/assignment/${id}/start`, { method: 'PUT' });

  // 2. 获取assignment对应的order_id
  const assignment = assignments.find(a => a.id === id);

  // 3. 更新order状态为"生产中"
  await fetch(`/api/schedule/${assignment.order_id}/status`, {
    method: 'PUT',
    body: JSON.stringify({ status: '生产中' })
  });

  // 4. 重新加载任务
  loadTasks();
}
```

### 3.2 师傅工作台 - 完成任务

```javascript
// 当前：只是显示alert，没有真正更新状态
document.getElementById('completeForm').onsubmit = async function(e) {
  e.preventDefault();
  alert(`任务完成！`);
  closeModal('completeModal');
  loadTasks();
}

// 应该：调用API更新assignment状态，检查是否可以完单
document.getElementById('completeForm').onsubmit = async function(e) {
  e.preventDefault();
  const id = document.getElementById('completeProgressId').value;

  // 1. 更新assignment状态为"已完成"
  await fetch(`/api/agent/assignment/${id}/complete`, { method: 'PUT' });

  // 2. 获取assignment对应的order_id
  const assignment = assignments.find(a => a.id === id);

  // 3. 检查该订单的所有工序是否都完成
  const checkResult = await fetch(`/api/agent/check-complete/${assignment.order_id}`);
  const { canComplete } = await checkResult.json();

  // 4. 如果可以完单，更新order状态
  if (canComplete) {
    await fetch(`/api/schedule/${assignment.order_id}/status`, {
      method: 'PUT',
      body: JSON.stringify({ status: '已完成' })
    });
  }

  closeModal('completeModal');
  loadTasks();
}
```

## 四、API接口清单

### 4.1 需要新增的API

| API | 说明 |
|-----|------|
| `PUT /api/agent/assignment/:id/start` | 开始工序 |
| `PUT /api/agent/assignment/:id/complete` | 完成工序 |
| `GET /api/agent/check-complete/:orderId` | 检查订单是否可以完单 |

### 4.2 需要修改的API

| API | 修改内容 |
|-----|----------|
| `PUT /api/schedule/:id/status` | 更新订单状态，记录状态历史 |

## 五、数据表关系

```
orders (订单表)
├── id (主键)
├── order_no (订单号)
├── status (状态: 待排产/生产中/已完成/已取消)
├── completed (完单标记: 空/完单)
└── ...

assignments (分配表)
├── id (主键)
├── order_id (外键 → orders.id)
├── step_name (工序名称)
├── worker (负责师傅)
├── status (状态: 待开始/进行中/已完成)
└── ...

order_status_history (状态历史表)
├── id (主键)
├── order_id (外键 → orders.id)
├── from_status (原状态)
├── to_status (新状态)
├── changed_by (操作人)
└── changed_at (操作时间)
```
